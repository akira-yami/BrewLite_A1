## 2. Implementation và double-charge guard

- Idempotency-Key được lưu cùng request hash (Order, method, amount); amount do API lấy từ Order trong database.
- Reuse một key với payload khác trả IDEMPOTENCY_KEY_REUSED.
- Replay một payment cùng key/hash đang PROCESSING trả PAYMENT_IN_PROGRESS; payment đã hoàn tất trả lại kết quả cũ.
- Payment creation chạy trong transaction có Order row lock; kiểm tra trạng thái và thời hạn giữ chỗ trước khi tạo payment.
- Trước khi tạo Payment mới, repository kiểm tra xem Order đã có Payment PROCESSING hay chưa. Key khác nhưng cùng Order đang có attempt hoạt động cũng bị chặn bằng PAYMENT_IN_PROGRESS.
- Migration thêm PostgreSQL partial unique index payments_one_processing_per_order_key trên payments(order_id) với predicate status = 'PROCESSING', tạo invariant ở database.
- Khi Prisma trả P2002, service đọc lại Idempotency-Key để phân biệt payload mismatch (IDEMPOTENCY_KEY_REUSED) với active-payment conflict (PAYMENT_IN_PROGRESS).
- Gateway I/O chạy ngoài transaction đang giữ Order lock; sau đó Payment và Order được cập nhật trong transaction.

1. **VNPay chưa được triển khai trong diff PR #35 hiện tại.** Không có adapter, payment URL creation, IPN endpoint, Return URL flow hoặc merchant Sandbox proof. Không dùng tài liệu Coverage này để tuyên bố VNPay end-to-end đã hoàn tất.
2. Nếu muốn phát hành VNPay, cần implementation riêng: ký/xác minh callback, merchant/amount validation, idempotent IPN processing, Return URL chỉ hiển thị trạng thái, sandbox test và quy trình late-success/refund/reconciliation.
3. Payment PROCESSING có thể cần quy trình phục hồi/đối soát nếu tiến trình dừng sau khi tạo Payment mà chưa ghi kết quả gateway; không mở attempt thứ hai chỉ để “giải phóng” trạng thái.
4. Trước khi apply partial unique index trên database đã có dữ liệu, chạy preflight:
   
       SELECT order_id, COUNT(*)
       FROM payments
       WHERE status = 'PROCESSING'
       GROUP BY order_id
       HAVING COUNT(*) > 1;

   Phải xử lý các nhóm trùng trước khi áp dụng migration.
5. Chưa có bằng chứng lịch sử RED-before-GREEN theo từng thay đổi cho toàn bộ feature; regression tests hiện có không thay thế chứng cứ TDD lịch sử.
